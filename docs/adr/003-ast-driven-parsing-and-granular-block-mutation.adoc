= ADR-003: AST-Based Block Parsing with In-Place Mutation Pipeline
:status: Accepted
:date: 2026-09-01
:toc:
:icons: font
:sectnums:

[NOTE]
.Status: Accepted
Notes Plus utilizes a strongly typed Abstract Syntax Tree (AST) with atomic block-level mutation routines, guaranteeing document formatting integrity during in-place edits.

== Context

A mobile note application requires fast, interactive operations on specific document sections:

* Toggling an interactive task checkbox (`[ ]` <-> `[x]`).
* In-place editing of a single paragraph or code block without re-parsing the entire document.
* Appending a new bullet item or section to the daily journal.
* Re-ordering or formatting tables.

****
.The Problem
Using ad-hoc regular expressions or naive string replacements for partial document updates easily corrupts surrounding formatting, breaks nested lists, or mangles delimited blocks.
****

== Decision

Implement a strongly typed AST parser and mutation engine in `notesplusplus-core`:

1. *Typed AST Representation*: Parse AsciiDoc into recursive `Block` nodes (Paragraph, Heading, List, Table, CodeBlock, Admonition, Quote, Sidebar, PageBreak) containing structured `InlineSpan` tokens.
2. *Deterministic Re-Serialization*: Implement `ToAsciiDoc` serialization on AST blocks to round-trip modified ASTs back to valid AsciiDoc markup without whitespace or formatting drift.
3. *Atomic Mutation Pipeline (`mutate_page_blocks`)*: Channel all partial updates through a single atomic pipeline.

=== Block Mutation Flow

[source,ascii]
----
Disk (.adoc file)
      │
      ▼ Read file
[ Parser ] ────► AST (Vec<Block>)
                      │
                      ▼ Apply closure (e.g. toggle checkbox) // <1>
                 Modified AST
                      │
                      ▼ Serialize (ToAsciiDoc)               // <2>
                 Updated .adoc Text
                      │
                      ├───────────────────────┬───────────────────────┐
                      ▼                       ▼                       ▼
          Atomic Write to Disk     Update SQLite FTS5      Notify QML Bridge
----
<1> The mutation closure receives mutable references to target blocks.
<2> Re-serialization preserves exact block delimiters, attributes, and table formatting.

== Code Example: Rust AST Block Structure

[source,rust]
----
pub enum Block {
    Paragraph { spans: Vec<InlineSpan>, .. },
    Heading { level: usize, spans: Vec<InlineSpan>, .. },
    List { items: Vec<ListItem>, ordered: bool, .. },
    Table { columns: Vec<TableColumn>, rows: Vec<TableRow>, .. },
    CodeBlock { language: Option<String>, content: String, .. },
    Admonition { kind: AdmonitionKind, content: Vec<Block>, .. },
    Sidebar { title: Option<String>, content: Vec<Block>, .. },
}
----

== Consequences

=== Positive / Utility Delivered

* icon:shield[] *Guaranteed Structural Integrity* -- Partial edits and checkbox toggles cannot corrupt surrounding blocks, table rows, or code fences.
* icon:bullseye[] *Single Source of Truth* -- Eliminates duplicate file I/O, parsing, and re-indexing logic across the codebase.
* icon:mobile[] *Fine-Grained UI Delegates* -- QML delegates can render individual blocks natively (e.g., specialized Table, Code, and Checklist components).

=== Trade-offs & Mitigations

[CAUTION]
.In-Memory AST Allocation
Parsing large documents into an in-memory AST introduces slight CPU overhead. This is mitigated by linear line scanners, pre-allocated vector buffers, and background thread execution.
